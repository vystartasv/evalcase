ASSERTION MATRIX

The outcome earns its status one row at a time.

Cases describe the expected contract. Outcomes record what happened. evalcase keeps those two artifacts separate and compares them in order.

REPORT PIPELINE

Case → outcome → report.

No hidden execution sits behind the check. JSON values remain data; reports are deterministic JSON or text.

  1. 01
    Define

    Set case id, input metadata, steps, expected status, result, and duration bound.

  2. 02
    Record

    Provide run_start, ordered tool_call/tool_result pairs, and run_end as JSONL.

  3. 03
    Evaluate

    Match ids and fields, then sort stable diagnostic codes and paths.

  4. 04
    Report

    Print human-readable output or the documented report JSON schema.

BOUNDARIES

Assertions, not judgement.

The CLI reads two named inputs, validates them, and writes only an explicitly requested report file.

Explicit non-goals

No model, judge, network, sandbox, runtime, framework adapter, code execution, templates, expressions, or quality inference.

Security: input is data-only; malformed JSON, unknown fields, bad ordering, duplicates, and contract violations get stable exit codes.

QUICKSTART

Run one recorded case.

The checked-in happy path uses no API key, model, network, current timestamp, or agent runtime.

git clone https://github.com/vystartasv/evalcase.git
cd evalcase
bun install --frozen-lockfile
bun src/cli.ts check fixtures/happy.case.json fixtures/happy.outcome.jsonl
bun src/cli.ts report fixtures/happy.case.json fixtures/happy.outcome.jsonl --json
bun src/cli.ts demo

LOCAL EVIDENCE

Stable outputs

0 means all assertions pass.

1 means valid contracts with a failed assertion.

2 / 3 cover malformed input or invalid contracts.
